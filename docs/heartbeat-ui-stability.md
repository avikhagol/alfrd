## Findings and implementation

The transcript already keyed messages, activity islands, and mailbox forms. The remaining disruption came from composer autogrow and attachment redraws on ordinary view updates; schedule controls rebuilding on identical polling responses; native selector option replacement; header replacement while its conversation menu was open; and the Studio console forcing every log redraw to the bottom. A separate scroll bug treated a text selection in the composer as a selection in the transcript.

`js/utils/refresh.js` extends the spinner fix's source-markup comparison rather than comparing browser-serialized HTML (which normalizes SVG paths). `sourceHTML` skips identical fragments and retains root offsets. `refreshHTML` additionally patches stable elements, changed attributes, and changed text in place, preserving nested scroll offsets, textarea contents, and disclosure state. It defers fragments containing focused controls or an open menu/dialog, retains only the latest pending source, and applies that source on focus release/close. Source caches also track the root's first child so another renderer taking ownership invalidates the cache.

Composer geometry changes now happen only on text edits, explicit session changes, sending, or real width changes. Ordinary refreshes update routing and action availability without resizing the textarea. A same-session draw no longer starts another schedule fetch: the schedule controller already owns polling and focus refreshes. Unchanged attachment chip markup keeps the same chip nodes.
