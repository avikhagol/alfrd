## Decisions

All choices here are made by design; no owner decisions remain.

1. Preserve Obsidian Orbit and Daylight Orbit shell themes. Add chat-scoped semantic aliases; do not recolor the entire app cyan. Use cyan for execution, indigo/purple for identity and existing indigo primary actions.
2. Keep local Inter/system sans and JetBrains Mono. Translate Stitch's Geist sizing into existing fonts; add no font downloads, Tailwind runtime, Material Symbols or dependencies.
3. Keep a continuous conversation. Earlier messages and final answers remain expanded. Only tools, attempts, raw protocol and supplementary usage collapse.
4. Agent identity is stable by configured key, with text, role and initials. Color indicates identity independently of task status. No provider logos or remote avatar URLs.
5. Keep timestamps visible at 12 px. Group adjacent messages visually only; never combine their IDs or infer request membership from time.
6. Preserve the reader's anchor, focused controls, selections, tail scroll and open/closed disclosures during updates, including completion. Never auto-collapse explicitly opened output.
7. Keep one composer implementation and one draft per project/session for both page and dock. Enter sends; Shift+Enter inserts a newline; IME composition never dispatches.
8. Autocomplete selection inserts a command/mention. Slash commands execute only on the next explicit submit, so browsing hints cannot accidentally create a session or open setup.
9. Keep Send and Stop as separate controls while work runs. Stop means the current request's cancellable task set, with a concrete confirmation; it never sends draft text or promises rollback.
10. Attachments stay within the existing upload capabilities and limits. No new arbitrary-file endpoint or URL attachment behavior.
11. An island represents a task, with attempts nested below it; planning/repair/replan/summary remain labelled orchestrator steps. Progress is completed-task count, never an inferred percentage of one task.
12. Inline mailbox cards are the primary place to answer questions and permissions. Inspector/sidebar badges navigate to the same card, rather than creating a second form.
13. Search filters sessions locally by title, ID and available preview; it does not search message bodies or alter the selected session. Keep rename, delete safeguards and routing.
14. Keep current responsive boundaries: sessions overlay at ≤900 px; inspector overlay at ≤1280 px. Desktop dock remains 300–720 px wide, default 380 px; narrow dock is modal.
15. Separate per-area CSS and exclusive file owners permit five parallel workstreams. Keep startup assets unchanged; enforce the task's stricter payload target explicitly and disclose the inherited overage.
16. Retain native controls, explicit keyboard alternatives, reduced motion, both themes, 200% zoom, and 44 px touch targets. Essential information never depends on hover, color, pulse or animation.

## Layout and message thread

The full page has session navigation, conversation and optional inspector. At >1280 px use 220 px sessions + `minmax(0,1fr)` conversation + 320 px inspector only while opened. At 901–1280 px use 208 px sessions and inspector overlay. At ≤900 px conversation fills the host and Chats opens navigation overlay. At ≤640 px sheets fill the available view with 8 px inset. Keep header/composer outside the transcript's scrolling area, conversation content max-width 48rem, and `min-height:0` throughout the grid. Use host height, not `100vh - magic offsets`; console, notices and banner must remain accounted for. Wrap header actions at zoom. Only code/tables have horizontal scroll.

Each message is an article with stable message ID, 28 px decorative initials avatar (24 px in dock), visible display name, `@key`, optional role, and `<time datetime>` in the header. User says **You**; system says **ALFRD**. Orchestrator is labelled from session settings, not a hardcoded provider. Specialist label comes from its configured key; unknown/deleted keys remain visible. Derive purple/sky identity slot deterministically from the key, not message order, task status or display name. Initials are at most two characters and supplementary to visible names. The orchestrator uses its designated slot. Centralize message presentation in the thread-owned renderer so page and dock agree.

Visually group adjacent messages only when request, role and agent match, timestamps are known and within two minutes, and no intervening tool, decision or system event exists. Subsequent articles may omit repeated decorative avatar but retain a readable author label. Separate new request/speaker groups by 24 px, continuations by 8 px. Use request IDs from `threadGroups`; preserve chronological ordering and synthetic task-result deduplication. Do not fold completed requests or hide answers behind a turn summary.

Timestamps always show local HH:MM; show a date separator when the calendar date changes. Full localized date/time and timezone are available as accessible text/title. Missing timestamps show no fabricated time. Keep semantic HTML and full timestamp accessible on touch.

Render message markdown through the existing sanitized markdown renderer/cache. Preserve paragraphs, headings, lists, links, fenced code, tables, artifacts and literal user JSON. Code has language label if supplied and **Copy code**; announce **Copied** or **Couldn't copy. Select the code and copy it.** Long lines scroll inside a labelled keyboard-focusable region. Do not execute HTML, protocol strings or links as actions. Keep raw protocol optional and collapsed; `presentMessage` continues to produce readable result summaries without rewriting ordinary user JSON.

Request activity sits after the user's message and before results. Keep a concise line such as **Working · 2/5 tasks complete · 1m 12s · $0.042** and the current server step. **Details** holds task islands/attempts; **Usage** holds supplementary counts. New tools and raw protocol start closed; active request Details may initially open. Native details have stable keys scoped to project/session/request/task/unit. Preserve explicit true and false on polls, navigation back and completion. Failed tools keep an error summary visible outside the collapsed output. Show only recorded public output, never invented thoughts.

Auto-follow only when within 24 px of the bottom and no text selection or focused output control would be disturbed. Otherwise preserve visible message anchor + offset and show sticky **Jump to latest · N new** above the composer. Count new messages/events, not every tail poll. Activating scrolls to the end, resets count and resumes following; keep focus on a stable button or move to the labelled log if the button disappears. Never focus the composer from a background update. Apply the same policy independently to each output tail. Missing older history loads on explicit **Load earlier messages**, preserving the anchor; do not fetch every full transcript upfront.

## Composer

Use the shared textarea and attachment tray in page and dock. Minimum two lines, grow on typing, paste, draft restore, session selection and width changes up to `min(240px, 40dvh)`; then scroll internally. Reset height after accepted send. Keep 12 px padding, 8 px control gaps, safe-area bottom inset and `100dvh` host layout so the mobile keyboard leaves the input and Send reachable.

Visible short helper: **Enter sends · Shift+Enter adds a line**. Label remains **Message**; placeholder **Ask the orchestrator, @agent, or /help**. A target hint says **To orchestrator @key** or **To @key directly**; unknown mentions produce an inline error and no request. Leading slash and mention rules stay compatible with `data/chat.js`.

| State | Required behavior |
| --- | --- |
| Empty | Send disabled for whitespace with no accepted attachments; keyboard cannot bypass. |
| Ready | Send enabled for text or accepted image refs. No optimistic clearing. |
| Uploading | Show per-file upload status; disable Send and explain **Wait for uploads to finish**. Text remains editable. |
| Sending | Send says **Sending…**, disabled; prevent duplicates in either composer. Keep draft until matching HTTP 201 acknowledgement. |
| Running | Send stays available for another supported request. Show separate **Stop request** for the newest active request with cancellable tasks. |
| Stopping | Confirmation names request and affected task count: **Cancel N queued or running tasks in request ID? Completed work is kept.** Then disable Stop, show **Stopping…**, reconcile server statuses. |
| Failed send | **Couldn't send. [message]** + Retry; preserve text, refs and idempotency key for unchanged content. |
| No session / loading capabilities | Disable dispatch with explanation; New session remains available when supported. |
| Read-only / unavailable | Preserve readable draft; explain server capability and expose reconnect/setup action as applicable. |

Stop uses the existing per-task cancel contract and `canCancel`, scoped to a concrete request. Freeze its task IDs at confirmation, then recheck current eligibility before each call. Report partial failure as **Stopped X of N tasks. Y couldn't be stopped.** with retry for the remaining IDs. If planning has no cancellable row yet, show **Planning cannot be stopped yet** with disabled Stop; do not fabricate a request-cancel endpoint. Stop never cancels another request or revokes completed work.

The component accepts optional `stopState()` and `onStop()` callbacks; callers own API actions. Existing callers without them keep functioning. Bind Enter only without modifiers, when not composing; Shift+Enter remains newline even if hints are visible. Ignore Enter/Tab hint handling during IME. Up/Down selects listbox option; Enter/Tab inserts it and retains caret; Escape dismisses hints before any enclosing sheet. Pointer selection also only inserts. Slash palette is the actual `/setup`, `/help`, `/new`, plus `/graph` on full page. No unsupported Stitch `/benchmark` or `/inspect` command. Unknown commands show current helper error; leading space remains the documented escape to send literal slash text.

Keep existing accepted attachment refs, upload limits, capability warnings, thumbnail/status and remove/retry controls. Do not imply all files are supported: use **Attach images** where only images are accepted, and display effective limits from capabilities. Paste image and file picker share validation. Removal during upload must not resurrect a chip after an asynchronous response. Failed files stay marked with Retry/Remove and block dispatch until resolved or removed. Report unsupported type, oversized file and unsupported image-consuming agent next to the tray. Text paste remains text. Session changes isolate drafts/refs; only accepted refs persist through reload, never raw file bytes. Storage failure says **Draft kept in memory; browser session storage is unavailable.** Keep `client_message_id` recovery and do not clear edits made while a prior send is in flight.

## Parallel-agent activity islands

Within each request's Details, show a responsive grid of task articles (minimum card width 260 px; one column in dock/phone). Each island has task title/row, avatar + owner, role/model when reported, text status + icon, current step, elapsed time, recorded cost and dependency summary. One task stays in one grid position while its status changes; use request/task identity. Attempts appear inside it with unit identity and attempt number, so retries retain previous output. Orchestrator calls have a distinct step row, not an extra completed task in the progress denominator.

Show request progress **2 of 5 tasks complete**; the bar uses `done / total`, with failed/blocked/cancelled counts separately labelled. Zero tasks says **Planning tasks…**, no determinate bar. Single-task islands show status/step rather than fake 45/78/94% values from Stitch. A step waiting on mail includes **Open question** or **Review permission** with the exact message ID navigation. Dependency-blocked and user-decision states must remain distinct.

| Runtime state | Island presentation |
| --- | --- |
| queued / waiting | Neutral clock + **Queued** / **Waiting on dependencies** and dependency IDs. |
| running | Cyan icon + **Running**, actual step and elapsed time. |
| retrying | Warning icon + **Retrying · attempt N**, retain prior failure. |
| needs_decision / waiting step | Amber **Needs your answer**, link to inline mailbox. |
| done | Success check + **Done**, final time and reported cost. |
| failed / blocked | Error icon + distinct **Failed** / **Blocked (dependency failed)**, readable reason, Inspect; Retry only when existing contract allows. |
| stopped / cancelled | **Stopped (budget)** / **Cancelled**, final values, no running animation. |
| unknown | **Unknown**; keep raw status accessible, never imply success. |

Timers update once per second while visible and active; freeze at authoritative finish time. Missing time/cost is **—** with **Not reported**, never $0.000. Show reported zero as zero. Format with existing duration/money helpers; expanded usage distinguishes new input, cache read/write, output, tool calls and session/request totals. Do not sum request totals and task totals together. Show cost/time budget warnings at 80% and limit; client warning alone does not stop execution.

A collapsed **Recorded output** contains tail selector 40/100/200/400 lines, Open log, follow/jump, and optional raw protocol disclosure. Display last three public collaboration messages as optional preview with **Team messages** disclosure; do not fabricate collaboration or inference throughput. Use the existing shared subscription per project/session; summary cards must remain fresh even if output is closed, but closed output must not request expanded tails. Keep 40-line baseline, 400-line ceiling and batches of ≤32 units; no second polling loop. On hidden document/closed dock unsubscribe or suspend visibility. When an item disappears from running results, retain the final explicit unit read. Revision/generation guards prevent stale snapshots from rolling back status.

## Sessions, dock and inline mailbox

Session sidebar has heading, New, labelled **Search sessions** input, clear action, and existing **Needs me** toggle. Filter by case-insensitive substring of title, ID and already available last-message preview; combine with Needs me. Keep query in memory per project for this visit. Search never fetches transcript bodies. Show **N of M sessions** after input and **No sessions match “query”.** with Clear search. Use current server ordering and preserve focused row across refresh; do not reorder a focused/editing row under the user.

Each row shows title (maximum two lines), one-line preview, available last activity time, active count and pending-user count. Full text is available accessibly. Selected link uses border + `aria-current="page"`. Rename and Delete appear on hover/focus and remain visible for coarse pointers. F2 renames focused row; Enter saves trimmed, nonempty title (120 character maximum); Escape restores it. Failed rename keeps input and typed text with retry. Delete retains existing permanent-deletion confirmation and active-request refusal. After deletion select adjacent surviving row, otherwise focus New. New session selects it, retains old draft, folds desktop list as today and focuses composer after load. Back/Forward/reload restore route/session.

Dock shows the same session/draft/thread/mailbox, a compact request summary, session selector, New, Open full and Close. Search can appear in a small session picker owned by dock; do not add global search. Open full preserves project/session and draft, closes the duplicate interactive dock, and opens the same session without resubmission. Keep dock width preference and separator keyboard behavior (Left grows, Right shrinks by 20 px; Shift 80 px; Home 720 px, End 300 px). At ≤900 px use a labelled modal dialog, inert background, trapped focus and return to trigger. Sessions and inspector overlays also trap focus while modal, and only one sheet is open at a time. Desktop dock is a nonmodal labelled complementary landmark; never trap its focus.

Inline pending questions/permissions sit immediately under their request activity summary, outside Details/Usage and before results. Sort by existing pending/priority order; resolved cards retain their chronological context. Each card names sender, task/request, question/action, options, expiry and scope. Permission shows **Approve once** and **Deny**; make the exact action, folders/commands and supplied action hash inspectable before approval. Never preselect approval, auto-submit, treat a mailbox read as authorization or suggest UI approval overrides sandbox policy. Questions use radio options plus optional written answer and **Send answer**. Keep legacy blockers usable if mailbox is unsupported; avoid duplicate actionable cards for the same ID.

One stable form per message ID retains unsent answers, radio choice, focus and expanded details across polls. Page and dock share resolution through the existing mailbox subscription and server version checks. Send expected version, exact supplied action hash and stable retry idempotency key. In-flight disables that form only. Resolution says **Approved once**, **Denied**, **Answer recorded**, **Answered elsewhere**, **Expired** or **Cancelled**; no stale poll re-enables it. HTTP 409 refreshes current state and requires renewed action when appropriate; never replay approval against a changed hash. Retry ordinary transport failure with draft preserved. Unknown expiry must not be guessed. Navigation from Needs me/step/graph deliberately reveals and focuses the inline card; background arrivals never scroll or steal focus. Announce one short **Permission requested by @key** status, not its full arguments.

## Empty, loading and error states

| Context | Copy and recovery |
| --- | --- |
| No sessions | **Start a conversation with your agents.** New session and Setup; show configured orchestrator/roles when known. |
| Empty selected session | **What would you like the agents to do?** Offer text-insertion prompts **Explain this project** / **Plan a change**; selecting does not send. |
| No tasks / output / mail | **Tasks appear after planning.** / **No recorded output yet.** / omit empty mailbox. |
| Initial load | **Loading sessions…** / **Loading conversation…**, stable reserved space and `aria-busy`; no fake message bubbles. |
| Refresh | Keep current content usable; do not flash loading over known transcript. |
| Session load failed | **Couldn't load this conversation.** Retry; keep last good content if available and indicate it is stale. |
| Disconnected | **Updates paused — reconnecting.** Last updated time + Refresh; preserve draft and history. Distinguish intentional **Live updates off**. |
| Activity/mail unsupported | Existing compatibility notice + Open full transcript/legacy Decisions as applicable; no endless spinner. |
| Send/upload/rename/reply failed | Error next to affected control, preserve input; Retry has exactly that operation's scope. |
| Partial task failure | Visible failed island and readable summary; inspect/retry existing task, never automatically resend original user message. |
| Browser-only mode | **Chat needs alfrd serve: agents run on the server.** No enabled dispatch. Preserve experimental gating. |
| Session removed / 404 | Explain **This session is no longer available.** Refresh sessions/New; never silently send a draft to another session. |

All server strings are escaped/sanitized through existing paths. Operational errors can be copied or inspected but do not expose unrelated credentials. No automatic modal for a network error.

## Keyboard and accessibility

Preserve Alt+Shift+A dock, Alt+Shift+I inspector, F on focused graph, graph arrows/Enter/0, F2/Delete on session link, and native disclosure Enter/Space. Do not add global single-letter shortcuts or consume browser find. Global shortcuts remain suppressed in editable fields except the existing deliberate dock toggle exception. Escape priority: autocomplete → rename → innermost modal/sheet → enclosing dock. Closing returns focus to the actual invoker.

Tab follows visual order: header/session controls, transcript actions, inline prompts, composer, optional inspector. Use landmarks and labelled regions, message articles and headings. Do not put the whole rapidly changing transcript in a live region: use one small polite status for new-message count, completed send and transitions. Errors use `role="alert"` once per failed operation, not per poll. Timers/cost counters have `aria-live="off"`. Native listbox/combobox hints maintain active descendant and selection; group actions have names including task/message context. Use 2 px focus outline with 2 px offset, 44×44 touch targets (34 px separated desktop text buttons acceptable), visible controls at 200% zoom and 360 px width, reduced-motion static status icons, selectable code and non-color status text. No hover-only timestamps or instructions.
