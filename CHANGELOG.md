# Changelog

## [0.2.2]

- **Agent sequences.** `repeat.sequence: [claude, claude, codex, …]` sets the order of turns; `iterations` is now the **total number of turns** (custom passes and `passes:` also accepted). New agent-loop projects use it; older projects (`repeat.iterations` + `steps`) keep counting passes unchanged.
- **Agent agnostic.** Built-in adapters for Claude and Codex, and a `generic` adapter for any stdin→stdout CLI (`adapter:`, `model_option:`). Studio project creation takes an agent sequence; `alfrd projects create --sequence`.
- **Fallback models.** `fallback_models:` per entrypoint or turn. Claude uses `--fallback-model`; other agents are relaunched with the next model after a runtime failure (never after an invalid or rejected response).
- **Per-turn human edit and review.** `workflow.turns` sets `manual`, `human_review` or `after` for single turns; Studio's Agents dialog has a per-turn table.
- **Edit a running plan.** Handoffs → *Turns of this run* (or `alfrd plan turn`) adds review to any turn — including the running one — or changes human turns, delays and models of turns not yet started, for that plan only. The review gate now lives in the runner, after the command exits; **Reject and stop** (`alfrd plan reject`) refuses a held handoff. No plan CSV columns are added.
- **Delays.** `after: "+1h"` starts a step that long after the previous one finished; `waiting[]` reports `kind: delay`; **Run now** / `--after 0`.
- **Tasks.** The project's iterations are the maximum per task (enforced). With `loop.workspace: worktree` (new projects) each task gets its own git worktree at `<task>/workspace` on branch `alfrd/<task>`, so tasks run in parallel without sharing files. Overview lists tasks (turns, worktree branch, runs) above the run history; click one to filter.
- **Attempt records.** Each turn records `logical_turn_id`, `attempt_number`, `retry_of`, `treatment`, `run_kind`, `outcome`, `usage_source`, normalized `input_uncached_tokens`, and raw / trimmed / final prompt sizes with truncated sections.
- **Fix:** plan token totals mixed Claude's uncached input with Codex's cache-inclusive input; totals now add `input_uncached_tokens` (raw counters unchanged).
- **Delete permanently works.** Settings → Projects → Remove, after the exact name is typed, deletes ALFRD's files (alfrd.yaml, plan/targets/notes, `.alfrd/`, task bookkeeping) and forgets the project; other files stay. **Delete all files and folders** (unchecked by default) deletes the whole folder; unsafe folders (home, top-level, symlink, the runtime database, a folder with another project) are refused, as are projects with active runs.
- **Setup forms.** `quickstart:` in alfrd.yaml (or the template) declares forms with `textbox`, `textarea`, `number`, `toggle`, `path` (server folder browser), `select` and `list` fields. AVICA's form fills `avica.inp`; the agent loop's sets the agents' commands, models, sequence, review and workspace. Overview → Get started → *Open the setup wizard*.
- **All settings form.** Settings → *All settings* (replacing Settings fields) shows every alfrd.yaml key as a field: checkboxes for true/false, choices for known options (execution mode, on_failure, loop workspace, entrypoint adapter, artifact kind, …), numbers, one-per-line lists and collapsible groups per section and list item. Known keys that are not set show their defaults; ↺ removes a key. A filter box finds keys. Edits rewrite only that top-level section of the draft.
- **Fix:** new AVICA projects showed "bad mapping indentation" in the Studio. ALFRD now writes alfrd.yaml without wrapped lines (multi-line text as `|` blocks), and the Studio's YAML reader also accepts wrapped plain and quoted strings. Every template is checked to parse the same in Python and the Studio.
- **Fix:** an alfrd.yaml that does not parse was read as empty, so `alfrd plan new` / `plan run` reported unknown or no steps. Running, planning and the setup wizard now stop with the file, line, column and YAML problem (e.g. `alfrd.yaml line 141, column 1: invalid YAML: expected <block end>, but found '-'`), and a file whose top level is not a mapping is refused. Studio views still open while the file is being fixed.
- **Agent steps everywhere.** A step with a Claude/Codex command or `category: Agent` in any workflow (e.g. an AVICA review step) now works like an agent-loop turn: recorded as an agent with its model and token usage (Resource usage shows the token table; Claude needs the step's `output_file`), the prompt sent is kept per attempt, a retry is told how the previous attempt ended, and an earlier answer in `output_file` is moved into the attempt's folder instead of refusing to start.
- **Settings → All settings:** add list items (shaped like the first one), keys and top-level settings, and remove items.
- **`alfrd serve` runs on waitress** (a production server) instead of Flask's development server; `--debug` keeps the development server. Fix: the live-update stream sent a `Connection` header that WSGI servers reject.
- **Long agent plans survive a crash.** Agents keep a checklist (`PROGRESS.md` in a task's worktree, `PROGRESS-<task>.md` in a shared folder; `loop.progress`, on by default, `false` = off), read it first and tick items off, doing what fits in the turn (the prompt states the turn's time limit). A retried turn (cell → *Retry (todo)*, or *Retry N*) is told how the previous attempt ended and to check the checklist and `git diff` before continuing. The agent-loop template shows the checklist as a *Progress* panel.
- **Start at a time.** A plan can start later: Run dialog → *Start at*, or `alfrd plan run --at "02:00"` (the next 02:00) / `--at "2026-10-07 02:00"` (at most 7 days ahead). It shows as *Scheduled · starts …* with **Run now** (`alfrd plan start-now`); a scheduled plan whose runner stopped (e.g. a reboot) is restarted by reconcile. A step can wait for a clock time too: `after: "02:00"` in alfrd.yaml (quote it; YAML reads a bare 02:00 as a number), Workflow → Runs → cell menu → *Start step at…*, or `alfrd plan turn <plan> <step> --after 02:00`; the first step of a plan can now wait as well.
- **Fix:** a row whose next step waited for its delay took a run slot, so with one target at a time the other targets sat idle until the delay ended; they now go ahead meanwhile.
- **Studio:** the left sidebar and the Workflow step inspector start collapsed (they open on demand and remember your choice); the Workflow toolbar no longer has *Replace* for alfrd.yaml (edit it in Settings).
- **phaseshift** is in the AVICA step order again and skipped by default (`steps: {phaseshift: {skip: false}}` runs it).
- **Skip template steps.** `skip: true` on a step in alfrd.yaml (top-level `steps:` or the workflow list) leaves it out of the workflow, the Studio and new plan CSVs; neighbours are chained and dependencies on it dropped. alfrd.yaml's own `steps:` definitions now override the template's in the runner too (previously only the workflow list did).
- **Fix:** a step's `after:` duration (start delay) is no longer read by the Studio as a dependency on a step called "+1h".
- **Baseline report.** `alfrd plan baseline` reports consecutive production turns with coverage gates (80% per field), retries, truncation and tokens per accepted result.
