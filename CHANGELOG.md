# Changelog

## [0.4.0.0]

- chat: expected outputs are fixed as absolute paths when a task is planned (`o1`, `o2`, … on the task record). A planned or delegated task whose output is outside the project and the folders agents may write, or is one of those folders itself, is refused. An agent reports a moved output with `outputs_changed: [{output, to, reason?}]` in its result or a mailbox message with code `OUT` (payload `output`, `to`). ALFRD checks every move (absolute, writable, not a folder root, not the same output twice, not its current path, not a path another output already has) and applies all or none: the output's `rev` goes up, the old path goes into its `history`, the thread gets an "ALFRD · output moved" message and the event `task.output_changed` is recorded. A refused move is a failed attempt, retried with the reason. Dependent tasks, replan and summary prompts, the final summary, promoted workflow steps and the Files tab use the current paths. The task inspector lists each output with a "moved · rev N" badge and its earlier paths. Fix: the Files tab showed an output given as `{path, description}` as a raw object.
- chat: `chat.delegate_decisions: off | questions | all` (default off) lets the orchestrator answer a task's blocker instead of asking you (`all` also lets it grant the access a task asks for); **Let orchestrator decide** on a pending decision hands over just that one. Bounded by `chat.bounds.max_replans`; repeated and mailbox-linked blockers stay with you. Each delegated choice is posted in the thread ("Orchestrator · decided for you").
- chat: scheduled checks (`chat.watch: {interval_seconds: 300, stall_seconds: 1800}`; 0 turns them off). `alfrd serve` checks each chat session periodically: a request whose tasks all finished is completed, a stopped runner with work left is resumed (not when paused or cancelled), and an agent process that has gone is reported. **Check now** in the Chat header and `alfrd chat check [--session SID] [--json]` (for cron) run the same check.

- superuser settings: one per-user file (`~/.config/alfrd/superuser.yaml`) read live by every `alfrd serve` / `alfrd gui`. The Studio page `/superuser` (`#/superuser`, loopback only) and `alfrd su show|set|reset|path|status` edit it: experimental features, hidden Studio sections and New-project templates, a read-only Studio and locks for plugins, plugin actions, project create/delete, runs, chat and file edits (403 `reason: superuser`; pausing, cancelling and stopping work are never locked), the live interval, and chat limits (max cost, max replans, allowed agents). The page also has statistics and an ops panel: active runs and running agents of every project with Stop / Pause / Resume / Cancel, the other servers, and system details. Command-line flags stay stronger. A broken file keeps the last good settings (or read-only). See docs/superuser.md.
- fix: in the Chat section one click on **New** (or Delete) acted once per earlier mount of the page (after project switches: five new chats). Click handlers are now bound once, in the chat dock too.

- chat sessions can be renamed and deleted: hover a session in the Chat list for **Rename** (F2) and **Delete** (Delete key, confirmed; refused while a request is active); `alfrd chat rename|delete`; `PATCH` / `DELETE /api/studio/projects/<p>/chat/sessions/<s>`. Delete removes `.alfrd/chat/<s>/` and the session plan `.alfrd/plans/chat-<s>/`. The chat list folds away with the sidebar button next to **New** (remembered per browser; **Chats** in the header shows it again).

- `alfrd serve --experimental-features` (also `alfrd gui`, env `ALFRD_EXPERIMENTAL_FEATURES=1`): Chat mode and the agent-loop template are experimental. Without the flag the Studio has no Chat mode preference (a Chat mode saved earlier in the browser is ignored: no Chat section, dock, Alt+Shift+A or chat runs in Workflow), New project offers only the basic and avica templates, the empty-workflow **Agent loop** card is hidden and `POST /api/studio/projects/create` refuses `template: agent-loop`. `GET /api/studio/session` reports `experimental`. Existing agent-loop projects and the CLI are unchanged.

- chat: permission blockers no longer loop. A blocker only access can fix (`kind: permission`, `requires`, or worded like a sandbox denial) goes to the user with options ALFRD applies itself: **Grant this task access and re-run** (folders/commands added to that task's next launch only, shown in its log and prompt; event `task.access_granted`), **Reassign this task to @agent** (event `task.reassigned`) and **Cancel this task**. The orchestrator may `reassign` or `cancel` in a decision but never grants. The same blocker with the same access is not replanned again (`task.stuck`), an unchanged re-run of a repeated permission blocker is refused, and `chat.bounds.max_replans` (default 3) caps replans per request. Chat rows always get `Bash(alfrd mailbox *)`; task prompts list the task's access and only the latest decision per blocker; the plan prompt says what each agent can reach.
- `agent_access`: globs expanded, folders passed as written and resolved (symlinks), bare command patterns also allow `<command> *`, read-only helpers added for Claude (`default_readonly: false` to turn off).

- chat mode toggle: Studio settings → Preferences → **Chat mode** (off by default, per browser) hides the Chat section, the dock, Alt+Shift+A, the palette entries and chat runs in Workflow.
- chat activity: every running call (orchestrator planning included) shows a live card with model, elapsed time and the end of its log (`GET …/chat/sessions/<s>/activity`); task messages link to their log and reply; orchestrator calls are nodes of the task graph (`kind`, `planned` edges); the graph opens full screen (button, **F**, `/graph`).
- chat `/setup` and slash commands (`/setup`, `/help`, `/new`, `/graph`): who does what with which model (orchestrator and escalation model, role → agent, model, fallback, availability from `GET …/chat/probe` / `alfrd chat probe`), saved into the `chat:` block (`GET/POST …/chat/settings`, conflict-guarded).
- free and local models: chat presets `ollama` (Codex `--oss`), `ollama-claude` (Claude Code on Ollama's Anthropic API), `hf` (Hugging Face router) and `local-llm` (new `python -m alfrd.llm_chat`, any OpenAI-compatible endpoint, text only). Agent fields `env` and `fallback`: an attempt that fails on a usage / rate / quota limit moves to the fallback agent without spending a retry (event `task.fallback`).
- chat sessions in Workflow → Runs (own group in the run picker, tasks × agents grid, Pause / Resume / Cancel, Open in Chat); Graph and List show the picked chat run's tasks; `plan_status` / the status API accept `chat-<sid>` and list chat runs with `run_kind: "chat"`. Chat runs never count as the active workflow run.

- chat dock: a collapsible right-side dock on every project view (Alt+Shift+A, top-bar icon, palette) with the active session's transcript, the composer (`@agent` completion, Enter / Shift+Enter), one progress line and **Open full**; open state and width kept in the browser, hidden in compact workflow mode unless opened by hand, loaded lazily, overlay at 900 px and below, live from the event stream. Listed in the shortcut reference.
- each chat task links to its unit logs and handoff folder; **Promote to workflow** previews a request's tasks as workflow steps and saves them into the active `alfrd.yaml` (history, changed-on-disk guard, cycle check). `POST …/chat/sessions/<s>/requests/<r>/promote`.
- usage accounting fixed: Claude token usage is summed over all `result` events of a run (a repeated event counts once) and the cost is the latest cumulative `total_cost_usd`.
- token and cost report: new input, cache read, cache write, output and cost per turn and plan (Schedule) and per task, request and session (Chat). Warning budgets `execution.warn_turn_cost_usd` and `chat.warn_task_cost_usd` add a badge and a `budget.warning` event (nothing is stopped).
- lean Claude startup (`lean`, `mcp`, `plugins`, `skills` on an entrypoint or step): `--strict-mcp-config`, `--mcp-config`, `--setting-sources project,local`, `--disable-slash-commands`. Off for existing projects; on in the agent-loop template and the chat `claude`/`sonnet` presets.
- chat orchestrator defaults to sonnet (`chat.orchestrator_model`) and escalates to opus (`chat.escalation_model`) for replans and plan repair; `chat.final_summary` now defaults to false (the final answer is built in code).

- chat: a task that reports done without its `expected_outputs` files is a failed attempt (retried within its bound); checked in code.
- configuration precedence is now fixed: `.alfrd/alfrd.yaml` > `alfrd.yaml` > `.alfrd.yaml`. The active file is the one read and written (Studio save, history, quickstart); lower files are ignored, never touched. The project root of `.alfrd/alfrd.yaml` is its parent folder.
- `alfrd projects create` and Studio *New project* write `.alfrd/alfrd.yaml` (`--config-location root` for the old layout).
- `alfrd manifest migrate [--dry-run] [--keep rename|shadow] [--force]` and Settings → Project move a root `alfrd.yaml` into `.alfrd/`; nothing is deleted.
- Studio API: `GET/POST /api/studio/projects/<p>/manifest/location|migrate`; save and manifest responses carry `manifest_location`.
- quickstart no longer bypasses the stale-file guard.
- plugin pages: `api.registerPage({id, title, render, order, icon, projectTypes})` adds an entry under **Plugins** in the Studio sidebar and a route `#/plugin/<id>?p=<project>` rendered in the main area, with loading, not-found, not-available and error states. `registerProjectSection` keeps working for short Overview summaries.
- plugin availability by project type: `Plugin.project_types` (default: every type), a global override in `plugins.json` and a per-project `plugins: {<id>: {enabled, project_types}}` block in the active `alfrd.yaml` (new schema key, written with the stale-file guard). An inapplicable plugin's panels, project actions, project checks and step hooks are skipped for that project, and its pages, sections and commands are hidden. Settings → Plugins shows *Not for <type> projects* with the reason and *Change where it applies…*. `GET /studio/plugins?project=` reports `available` and `unavailable_reason`.
- `.ms` discovery from the active manifest's `artifacts:` (`kind: directory`, patterns ending in `.ms`; `**` supported) at `GET /api/studio/projects/<p>/measurement-sets`, and a confined project explorer at `GET /api/studio/projects/<p>/files?path=` (no `..`, symlinks out of the project shown but not followed, `.ms` folders are leaves); plugins use them through `api.measurementSets`, `api.listFiles` and `api.fileExplorer`.
- Potter (alfrd-potter) moved from an Overview card to its own page with the declared Measurement Sets and the explorer fallback.
- workflow canvas: right-click (or Shift+F10 / Menu key) menus on empty space and on steps, *Add step here*, drag from a step's port to connect, disconnect from the menu or by clicking an arrow, delete, and a **Configure** inspector tab (command / entrypoint, dependencies, inputs, outputs, stage, time limit, start delay, status source, skip) — all on the workflow draft, saved through the active `alfrd.yaml`. Keys: N add, E configure, C connect (arrows + Enter), Delete, 0 fit, F fullscreen.
- dependency cycles, self-dependencies and unknown steps are refused on the canvas (with the cycle path) and by the server for every `alfrd.yaml` save (`history.save` / `save_manifest`, HTTP 400 *Invalid workflow dependencies: …*).
- run actions on the canvas: toolbar Pause / Resume / Start now / Cancel, *Schedule a run…* (Run… with +15 min / +1 h / +4 h), and per step Run, Stop, Retry, Skip, Open log.
- `POST /api/studio/projects/<p>/plans/<id>/units/<unit>/stop` stops one running command (SIGTERM to its process group via `control.json` `stop_units`, SIGKILL after `kill_grace`); the unit and its cell become `cancelled`, the rest of the plan continues. Also in the Runs grid cell menu.
- compact workflow mode (Alt+Shift+C, remembered) and fullscreen for the Workflow view.
- keyboard and browser: shortcut reference (`?`, palette, footer) with platform modifiers; global shortcuts (including Ctrl/⌘+K) ignore keys typed in fields; Back/Forward step through sections, projects and targets (history entries instead of replaced URLs) and reload restores them; warnings before losing unsaved `alfrd.yaml`, workflow-draft or Configure edits; a lost-connection notice; node focus rings.
- project chat (backend; docs/orchestration.md): sessions under `.alfrd/chat/<session>/`, messages go to the orchestrator, `@agent …` goes straight to one agent. Role presets in a new `chat:` block of alfrd.yaml (claude/opus orchestrator, sonnet for test planning and verification, codex for design and development, agy through the generic adapter) with per-request bounds (depth 2, 1 retry per task, $5, 2 h, 20 tasks). Tasks run as rows of the session's plan on the existing runner; the orchestrator is called only for a new message, a blocker addressed to it, and one final summary (`chat.final_summary`).
- versioned protocol `alfrd.orchestration/1`: JSON Schemas `orchestration_{envelope,task,result,blocker,decision}.v1.json`, strict validation, one repair attempt for an invalid plan; artifact refs `path@sha256` with selective retrieval (confined to the project, hash-checked, ranged, 256 KiB per read).
- plan CSVs (any plan) accept optional `depends_on` (start after these rows are done; blocked when one fails), `max_retries` (bounded automatic retries) and `max_seconds` (per-command limit) columns; a cell value `waiting` holds a row for a decision.
- Studio API `/api/studio/projects/<p>/chat/…` (settings, sessions, messages, decisions, task cancel/retry, artifacts) and `alfrd chat new|list|send|show|decide`. Events `task.*`, `decision.*`, `request.finished`, `budget.exceeded` in the session plan's events.jsonl.
- Studio **Chat** section (`#/chat/<session>?p=`): sessions, composer (Enter sends, Shift+Enter newline, `@agent` autocomplete with roles), transcript with agent result summaries and artifacts (selective retrieval), full transcripts loaded per attempt on demand, the task graph on the Workflow canvas renderer (read-only) with task details and Cancel/Retry, blockers with answer controls, and progress / cost / time against the request's bounds. Live updates come from the existing event stream; loading, empty, error and disconnected states.
- chat API: `GET …/chat/sessions/<s>/tasks/<row>/transcript` (attempts and sizes) and `…/transcript/<unit>/prompt|response` (paged, ≤ 256 KiB); task results record `at`.
- Settings → **Agent chat**: edit the `chat:` block (agents and role presets → entrypoint / model / adapter / persona / roles, orchestrator, final summary, concurrency, history, bounds); saves the active `alfrd.yaml` through the usual path with the changed-on-disk guard.
- **New project on a canvas** (`#/new-project`, and *Design on canvas…* in the New project dialog): start from a template's workflow or an empty canvas, add and connect steps (cycle check), assign agents and personas, list the first targets, validate, create (`.alfrd/alfrd.yaml` by default, root file optional) and open the project on Workflow with the first target selected. The draft survives a reload.
- `POST /api/studio/projects/create` accepts `draft: {steps: [{id, label?, category?, description?, entrypoint? | cmd?, role?, depends_on}], targets: [...]}`: validated on the server (ids, unknown or self dependencies, cycles, entrypoints, personas, target names) before any file is written; steps replace the first workflow's steps, targets go to `alfrd.targets.csv` (an agent loop takes one target: its first task's name).
