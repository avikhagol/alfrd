# Changelog

## [0.3.0.0]

- **Telegram status:** `/status` remembers a project and one or more targets across restarts, with per-target cards for finished, running, failed and next steps; `/status last`, `/status latest`, `/status new` and `/status NAME`, numbered pickers and five-entry pages make selection and browsing easier. See the [plugin README](examples/plugins/alfrd-telegram/README.md#commands).
- **`alfrd serve` needs an access token.** Every route except `/api/health`, `/version`, `/login` and the Studio's static files now needs the server's token, also on loopback: any local account could previously read plans, logs and handoffs and start plans. `alfrd serve` prints and opens `…/studio/?token=…`; the first visit trades the token for an `HttpOnly; SameSite=Strict` session cookie (`Secure` over https) and removes it from the address bar. Scripts send `Authorization: Bearer <token>`. Without it: 401 (browsers get a page saying how to get the link), and more than 10 wrong tokens per minute per address get 429.
- The token and session key are in `~/.config/alfrd/server-<port>.json` (mode 0600, removed on exit). **`alfrd url [--port]`** prints the link again. `--token` / `ALFRD_TOKEN` pins a token for proxies and scripts; `--no-token` turns the check off and is refused for non-loopback `--host`. A non-loopback `--host` warns that the token travels in clear text without TLS (use an https reverse proxy or `ssh -L`).
- **Status API:** loopback scripts now send the access token too; `ALFRD_API_TOKEN` keeps working as the Bearer for other hosts and is valid for `/api/v1/*` only. See [docs/status-api.md](docs/status-api.md).
- **Notifications.** Runners write structured events to `.alfrd/plans/<id>/events.jsonl` and send notifications themselves, so the server can be stopped. Routes go in `alfrd.yaml` `notify.routes` (desktop only) and in your `~/.config/alfrd/notify.json`: `desktop` (`notify-send` / `osascript`), `webhook` (https, optional HMAC-SHA256 `X-Alfrd-Signature`) and `command` (argv, message JSON on stdin; e.g. ntfy). Events of a plan within 20 s are batched; failures are retried and never delay a turn; a restarted runner doesn't resend. New `turn.idle` after `notify.idle_after` seconds (default 600) of silence. Notifications carry status and a Studio link, never handoff text. See [docs/notifications.md](docs/notifications.md).
- **Telegram.** New `via: telegram` route (`token`, numeric `chat_id`, optional `studio_url`), only in `notify.json`: plain-text messages (title, body, *Open in Studio* link), at most 4096 characters, no link preview. A wrong token or chat (400/401/403/404) is skipped; 429 and 5xx are retried. The token never appears in errors, logs or the Studio, which shows `token` and `chat_id` as "(configured)". The example plugin `examples/plugins/alfrd-telegram` adds `alfrd telegram run`, a bot for that one chat: `/status [project]`, `/runs`, `/log TARGET STEP` (30 lines), `/help`, and `/pause` / `/resume` after a Yes/No that expires in 5 minutes. Other chats get no answer; use a private chat, since anyone in a group chat can press Yes. See [docs/notifications.md](docs/notifications.md) and the plugin README.
- **Plugin settings and services.** Plugins can declare `settings` (`SettingField`: text, number, secret, bool; `required`, `pattern`), a `check(values)` and `services` (`Service`: a long-running `alfrd <command…>`). Settings → Plugins → **Configure** shows the form (a secret is write-only: *set* / *not set*, **Clear**), **Test**, and each service with Start/Stop/Restart, its state, last exit code and log, and *Start with the Studio*. Values go to `~/.config/alfrd/plugin-settings.json` (mode 0600), never `alfrd.yaml`. Services run as children of `alfrd serve` with `ALFRD_RUNTIME_DB` set, stop with SIGINT (SIGKILL after 5 s) and with the server, restart after 2/5/10/30 s and give up after 5 exits in 10 minutes, or at once on exit code 2 ("fix the settings"). Saving settings restarts a running service. Every change is a protected mutation recorded in `plugins/audit.jsonl` without values. See [docs/plugins.md](docs/plugins.md#settings-and-services).
- **Telegram plugin 0.2.0:** paste the bot token and the allowed chat id in Settings → Plugins → Telegram, check them with **Test** (`getMe`/`getChat`, sends nothing), and run the bot from there (*Background → Start*, optionally with every `alfrd serve`). One bot per token (a lock file); a rejected token or chat exits 2 instead of looping; network errors log their cause instead of `HTTP 0`. A `telegram` notification route without `token`/`chat_id` uses the saved settings.
- **Studio notifications.** Settings → Notifications lists the routes (secrets hidden) with **Send test**, and *Show browser notifications* shows reviews, failed/finished runs and idle turns while a Studio tab is open, also in the background. Toasts for routed events. Links `/studio/#/workflow?project=…&plan=…&unit=…` open that run and turn.
- **The Studio shows the working run.** It opens on the newest working run (a turn running, or waiting for review or a response; else another active run, else a scheduled one) instead of the newest run, labels scheduled runs "Scheduled HH:MM", and shows an "N active runs" switcher when more than one runs. A run you pick stays selected; when it ends and another is working, the Studio follows that one and says so.
- **Fix: a status note no longer replaces the handoff.** Claude prints one more result for each background task that ends, and alfrd used to keep the last one. A short note after the closing report ("the report above stands") replaced the report and failed the turn for missing headings. A result that has the handoff's headings is now kept; a later one replaces it only if it has them too.
- **Saving alfrd.yaml during a run asks first.** A running, paused or interrupted agent loop stops before its next turn when its alfrd.yaml changes. The Studio now lists those runs and asks before saving.
- **The first turn starts working.** Turn 1 used to be told to only plan and leave implementation to the next agent, so a detailed task still cost a planning turn. Now it starts on the task when it already says what to build, and plans first only when it's vague. `loop.contract.first` still overrides this.
- **Studio settings** keep one size: sections are in a sidebar (a strip on narrow screens) and only the section scrolls, so switching sections no longer moves the dialog. Up/Down arrows move between sections.
- **Studio header.** One row up to 1280 px wide. **Projects** (folder icon) opens New project, which has *Open existing project…* (and Open project has *New project…*); the separate New/Open buttons are gone. The Project and Target pickers keep a fixed width, shorten long names in the middle (the folder or suffix stays visible) and list full names, projects with their folder; two projects with the same name show their folder. Keyboard: arrows, Home/End, type to jump, Enter, Escape; a filter box past 8 entries. Import and Export share one **⇅** menu (also in the command palette, with New/Open/Switch project); Re-scan is an icon. The demo data loads only when used.
- `GET /api/v1/projects/<p>/plans/<id>/events?since=<seq>` (digits) returns the structured events as JSON.
- **`ALFRD_TRUST_PROXY=1`** makes `alfrd serve` read one reverse proxy's `X-Forwarded-*` headers (client address, https, host, prefix), so the session cookie is `Secure` behind a TLS-terminating proxy. The wrong-token counter now forgets addresses after the window and keeps at most 10 000.
- Studio: when the server answers 401 (e.g. after a restart with a new token), the Studio opens the access page once, stops further requests and the live-update stream instead of falling back to browser mode or retrying. The session cookie is named per port, so servers on different ports keep separate logins.
- **Plugins.** New `alfrd plugin list|info|install|remove|update|enable|disable|theme|new`. Plugins are Python packages with an `alfrd.plugins` entry point (`from alfrd.extensions import Plugin, PanelSpec`), installed into `~/.local/share/alfrd/plugins/site` (never alfrd's own environment) with alfrd's packages pinned, one install at a time, and removed file by file. Plugins run as you with access to your files: `install` warns and asks (`--yes`). A plugin that fails to load is listed with its error and never stops `alfrd serve` or the CLI; `alfrd serve --safe-mode` / `ALFRD_NO_PLUGINS=1` skips them all. Plugins can add `views.metadata` panel kinds and `alfrd <id> …` commands; browser viewers and converters activate independently, and Settings → Plugins includes Diagnostics and a persistent theme picker. See [docs/plugins.md](docs/plugins.md).
- **Themes.** A light theme, **Daylight Orbit**: `alfrd plugin theme daylight-orbit`, then reload the Studio (no restart). **Obsidian Orbit** stays the default and looks as before. Drop-in themes go in `~/.local/share/alfrd/themes/<id>/theme.css`; `alfrd plugin new <id> --kind theme` writes one with every colour token.
- **Install plugins from the Studio.** Settings → Plugins → Browse: choose a catalog (no default), review hash-pinned versions and dependencies, or use an advanced source with typed plugin-id confirmation. Install/update/remove run one at a time with a 10-minute timeout, live progress/logs and a Studio audit log (`plugins/audit.jsonl`; CLI changes are not recorded there). `--no-gui-install` shows terminal commands instead. Restart now preserves the login session, checks health before reloading, and confirms unsaved workflow edits.
- Studio Overview, agent loops: **All targets / Target only** above the run history (as in Results), where *Target only* keeps the runs of the task selected in the header. The row of task chips is gone; pick a task in the header instead.
- Studio: **Settings → All settings** shows the top-level keys; sections (loop, execution, workflows, …) open in **Advanced…**, a dialog with one section at a time and a filter. Remove buttons sit at the right of each item.
- Studio: when browser notifications are blocked, Settings → Notifications names the address to unblock and offers **Ask again**; the switch turns on by itself once they are allowed.
- Studio footer: CPU and RAM of the machine running `alfrd serve` (every 5 s while the tab is visible; `GET /api/studio/system`).
- **Faster start-up.** `import alfrd` and `alfrd.runtime` load their public API on first use, so the CLI, plan runners and each turn's shim no longer import pandas and SQLAlchemy at start (shim 0.9 s → 0.07 s, `alfrd --help` 0.7 s → 0.3 s). The runner wakes as soon as a turn's process exits, and checks whether alfrd.yaml changed without re-parsing it on every tick.
- **Fix: usage of two plans running at once.** Each command's processes are marked with `ALFRD_UNIT=<plan id>/<unit id>`; the unit id alone repeats across plans, so two plans with the same target and step counted each other's processes.
- **Fix: retrying the right plan.** Plans created within the same second are now ordered by creation time (`created_ns`), so *Retry failed* continues from the latest one.
- Tests run in parallel (`pytest -n auto -m "not serial"`, then `pytest -m serial`; `pytest-xdist` is in the `dev` extra), and on every push and pull request on GitHub. The full suite takes about a minute instead of twelve.
- Studio: `views.metadata` accepts panel kinds registered by plugins, and an unknown kind lists the known ones. Images and PDFs declared as project files open in a viewer from the full-file view.

### Removed

Code nothing in alfrd (or AVICA) used any more:

- The 0.1 project CLI: `alfrd init`, `ls`, `lsp`, `run`, `add`, `rm`, `inspect`, `nrun`, with the decorator API behind it (`alfrd.plugins`: `register`, `validate`, `validator`; `alfrd.Pipeline`, `PipelineRun`), `alfrd.core.project`, `alfrd.core.inspect` and `alfrd.core.workflow` (`WorkflowManager`). Use `PipelineCore` for Python pipelines and `alfrd.yaml` for projects.
- The old Flask dashboard (`/dashboard/` pages, templates and CSS); the Studio is the UI. `/` opens the Studio; `/api/*` is unchanged.
- `alfrd.core.viewers`, `alfrd.core.artifacts` and `alfrd.runtime.adapters` (`RuntimePipelineRunner` and the runtime event sinks), `alfrd.util`, the alias modules `alfrd.lib`, `alfrd.core.logger`, `alfrd.core.config`, `alfrd.core.manifest`, `alfrd.core.repository`, and `ALFRD_DIR`, `PROJ_DIR`, `get_project_dir`, `ProjectSchema`.
- An agent-loop run still active from before the current alfrd.yaml hash (comments and `history` ignored) now stops as changed; start it again.
- `alfrd gui` stays as an alias of `alfrd serve`.

## [0.2.2]

- **Agent sequences.** `repeat.sequence: [claude, claude, codex, …]` sets the order of turns; `iterations` is now the **total number of turns** (custom passes and `passes:` also accepted). New agent-loop projects use it; older projects (`repeat.iterations` + `steps`) keep counting passes unchanged.
- **Agent agnostic.** Built-in adapters for Claude and Codex, and a `generic` adapter for any stdin→stdout CLI (`adapter:`, `model_option:`). Studio project creation takes an agent sequence; `alfrd projects create --sequence`.
- **Fallback models.** `fallback_models:` per entrypoint or turn. Claude uses `--fallback-model`; other agents are relaunched with the next model after a runtime failure (never after an invalid or rejected response).
- **Per-turn human edit and review.** `workflow.turns` sets `manual`, `human_review` or `after` for single turns; Studio's Agents dialog has a per-turn table.
- **Edit a running plan.** Handoffs → *Turns of this run* (or `alfrd plan turn`) adds review to any turn — including the running one — or changes human turns, delays and models of turns not yet started, for that plan only. The review gate now lives in the runner, after the command exits; **Reject and stop** (`alfrd plan reject`) refuses a held handoff. No plan CSV columns are added.
- **Delays.** `after: "+1h"` starts a step that long after the previous one finished; `waiting[]` reports `kind: delay`; **Run now** / `--after 0`.
- **Tasks.** The project's iterations are the maximum per task (enforced). With `loop.workspace: worktree` (new projects) each task gets its own git worktree at `<task>/workspace` on branch `alfrd/<task>`, so tasks run in parallel without sharing files. Overview lists tasks (turns, worktree branch, runs) above the run history; click one to filter.
- **Attempt records.** Each turn records `logical_turn_id`, `attempt_number`, `retry_of`, `treatment`, `run_kind`, `outcome`, `usage_source`, normalized `input_uncached_tokens`, and raw / trimmed / final prompt sizes with truncated sections.
- **Fix:** plan token totals mixed Claude's uncached input with Codex's cache-inclusive input; totals now add `input_uncached_tokens` (raw counters unchanged).
- **Delete permanently works.** Settings → Projects → Remove, after the exact name is typed, deletes ALFRD's files (alfrd.yaml, plan/targets/notes, `.alfrd/`, task bookkeeping) and forgets the project; other files stay. **Delete all files and folders** (unchecked by default) deletes the whole folder; unsafe folders (home, top-level, symlink, the runtime database, a folder with another project) are refused, as are projects with active runs.
- **Setup forms.** `quickstart:` in alfrd.yaml (or the template) declares forms with `textbox`, `textarea`, `number`, `toggle`, `path` (server folder browser), `select` and `list` fields. AVICA's form fills `avica.inp`; the agent loop's sets the agents' commands, models, sequence, review and workspace. Overview → Get started → *Open the setup wizard*.
- **All settings form.** Settings → *All settings* (replacing Settings fields) shows every alfrd.yaml key as a field: checkboxes for true/false, choices for known options (execution mode, on_failure, loop workspace, entrypoint adapter, artifact kind, …), numbers, one-per-line lists and collapsible groups per section and list item. Known keys that are not set show their defaults; ↺ removes a key. A filter box finds keys. Edits rewrite only that top-level section of the draft.
- **Fix:** new AVICA projects showed "bad mapping indentation" in the Studio. ALFRD now writes alfrd.yaml without wrapped lines (multi-line text as `|` blocks), and the Studio's YAML reader also accepts wrapped plain and quoted strings. Every template is checked to parse the same in Python and the Studio.
- **Fix:** an alfrd.yaml that does not parse was read as empty, so `alfrd plan new` / `plan run` reported unknown or no steps. Running, planning and the setup wizard now stop with the file, line, column and YAML problem (e.g. `alfrd.yaml line 141, column 1: invalid YAML: expected <block end>, but found '-'`), and a file whose top level is not a mapping is refused. Studio views still open while the file is being fixed.
- **Agent steps everywhere.** A step with a Claude/Codex command or `category: Agent` in any workflow (e.g. an AVICA review step) now works like an agent-loop turn: recorded as an agent with its model and token usage (Resource usage shows the token table; Claude needs the step's `output_file`), the prompt sent is kept per attempt, a retry is told how the previous attempt ended, and an earlier answer in `output_file` is moved into the attempt's folder instead of refusing to start.
- **Settings → All settings:** add list items (shaped like the first one), keys and top-level settings, and remove items.
- **`alfrd serve` runs on waitress** (a production server) instead of Flask's development server; `--debug` keeps the development server. Fix: the live-update stream sent a `Connection` header that WSGI servers reject.
- **Long agent plans survive a crash.** Agents keep a checklist (`PROGRESS.md` in a task's worktree, `PROGRESS-<task>.md` in a shared folder; `loop.progress`, on by default, `false` = off), read it first and tick items off, doing what fits in the turn (the prompt states the turn's time limit). A retried turn (cell → *Retry (todo)*, or *Retry N*) is told how the previous attempt ended and to check the checklist and `git diff` before continuing. The agent-loop template shows the checklist as a *Progress* panel.
- **Start at a time.** A plan can start later: Run dialog → *Start at*, or `alfrd plan run --at "02:00"` (the next 02:00) / `--at "2026-10-07 02:00"` (at most 7 days ahead). It shows as *Scheduled · starts …* with **Run now** (`alfrd plan start-now`); a scheduled plan whose runner stopped (e.g. a reboot) is restarted by reconcile. A step can wait for a clock time too: `after: "02:00"` in alfrd.yaml (quote it; YAML reads a bare 02:00 as a number), Workflow → Runs → cell menu → *Start step at…*, or `alfrd plan turn <plan> <step> --after 02:00`; the first step of a plan can now wait as well.
- **Fix:** a row whose next step waited for its delay took a run slot, so with one target at a time the other targets sat idle until the delay ended; they now go ahead meanwhile.
- **Studio:** the left sidebar and the Workflow step inspector start collapsed (they open on demand and remember your choice); the Workflow toolbar no longer has *Replace* for alfrd.yaml (edit it in Settings).
- **phaseshift** is in the AVICA step order again and skipped by default (`steps: {phaseshift: {skip: false}}` runs it).
- **Skip template steps.** `skip: true` on a step in alfrd.yaml (top-level `steps:` or the workflow list) leaves it out of the workflow, the Studio and new plan CSVs; neighbours are chained and dependencies on it dropped. alfrd.yaml's own `steps:` definitions now override the template's in the runner too (previously only the workflow list did).
- **Fix:** a step's `after:` duration (start delay) is no longer read by the Studio as a dependency on a step called "+1h".
- **Baseline report.** `alfrd plan baseline` reports consecutive production turns with coverage gates (80% per field), retries, truncation and tokens per accepted result.
